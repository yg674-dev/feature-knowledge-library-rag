FEATURE: slice_is_in_battle TYPE: Model feature ENTITY: Video Slice VALUE: FLOAT64 · minute-level · SLA A DESCRIPTION Whether the given video slice is currently in a PK (battle) session between two live rooms. Returns 1 when the slice belongs to a room that is engaged in an active PK; 0 otherwise. Used for governance policies that treat PK sessions differently from normal broadcast (e.g. gift-boost scenarios, cross-room co-broadcast risk models). USAGE SCOPE Generic · applies to any live-room governance policy involving PK state. Not bound to a specific policy code. AI Q&A Widget · 悬浮窗方案说明
页面右下常驻 · 未来底层 agent 会同时对接 Lark 对话框（同一个 agent，两个入口）
Design Notes / 设计说明
Positioning · 定位
  • 页面右下常驻 Ask AI 按钮 · 与现有 Oncall 悬浮窗并存（本期不动 Oncall）
  • 点击弹出侧边面板（本 Sketch）· 支持最大化为居中 modal
  • 底层 agent 未来与 Lark bot 共用一套
Modes · 模式
  • Feature Discovery（本期唯一）—— 我该用哪个特征？逻辑是什么？稳定性如何？
  • Platform Oncall 合并—— P2 再课 Oncall 团队 对齐，本期不 block；届时评估：并入 Ask AI / 保留独立
Interaction · 交互
  • 示例 prompt 卡片 3 张 · 引导初次使用
  • 召回结果以 Feature Card 形式返回 · 点击跳 F2 详情
  • 为空时引导用户跳 F3 新建（"没找到 · 是否新建？"）
  • Score < 阈值：结果打灰 + "参考度低"标签
Rollout · 上线路径
  1. Phase 1（本期） · Ask AI 悬浮窗独立上线 · 只做 Feature Discovery · Oncall widget 不动
  2. Phase 2 · 记忆 / 多轮 / 收藏 + 与 Oncall 团队对齐是否合并
  3. Phase 3 · Lark 对话框接入（同一 agent 底座）
User Persona · 谁在问

雪荣团队等业务方 —— 现有 7000+ 特征里只知道自己提过的几十个，其余靠"抓着艺楠、加浩问"。本 widget 就是把这个"图书管理员"角色搬到平台上。
