Design Notes / 设计说明
Positioning · 定位
  • 页面右下常驻 Ask AI 按钮 · 与现有 Oncall 悬浮窗并存（本期不动 Oncall）
  • 点击弹出侧边面板（本 Sketch）· 支持最大化为居中 modal
  • 底层 agent 未来与 Lark bot 共用一套
Modes · 模式
  • Feature Discovery（本期唯一）—— 我该用哪个特征？逻辑是什么？稳定性如何？
  • Platform Oncall 合并—— P2 再课 Oncall 团队 对齐，本期不 block；届时评估：并入 Ask AI / 保留独立
Answer Pattern · 回答模式
  • 默认先解释用户问题可能涉及的业务口径，再按相关度排序展示 Feature Cards
  • 不标 Recommended · 只给轻量判断（Likely suitable / Likely not suitable / Need more context），最终决策留给业务
  • 用户明确搜 code / name 时 → 跳过解释，直接返回列表
  • 问题太泛且口径冲突明显（NEED_CLARIFICATION）→ 最多追问 1 轮选项式澄清，用户回答或 Skip 后必须返回 Feature Cards
Interaction · 交互
  • 示例 prompt 卡片 3 张 · 引导初次使用 · 对话在会话内连续追加（本期无跨会话记忆）
  • 召回结果以 Feature Card 形式返回（含 why matched / scope / SLA / data source / owner / usage example / risk）· 点击 View detail to confirm 跳 F2
  • LOW_CONFIDENCE · score < 阈值：结果打灰 + “参考度低 / Low confidence”标签 + 引导补充场景
  • NO_RESULT · 空结果：不编造答案，引导有 RAG 编辑权限的用户进入 F3 New feature entry · Ask AI；无编辑权限用户点击后弹申请权限弹窗，不进入写模式
  • Guardrail · 只消费 INDEXED Feature Knowledge，不编造特征逻辑；最终确认必须进入 F2 detail
Rollout · 上线路径
  1. Phase 1（本期） · Ask AI 悬浮窗独立上线 · 只做 Feature Discovery · Oncall widget 不动
  2. Phase 2 · 记忆 / 多轮 / 收藏 + 与 Oncall 团队对齐是否合并
  3. Phase 3 · Lark 对话框接入（同一 agent 底座）
